# 2.9.1 翻译结果恢复

## 已复现的问题

历史十站测试记录包含 17 次校验失败，但未保存错误类别和模型原始返回，因此不能逐条确认其原因。本次使用相同文本快照，复现了以下两类问题：

1. MDN 文本采集时删除了行内代码，句中留下空缺。旧提示词即使面对普通文本也会解释保护占位符，模型在空缺处生成了原文不存在的占位符，被保护校验拒绝。
2. 维基百科样本在字符上限处截断了半句话。真实返回的最后一项字符串没有闭合，整份 JSON 无法解析，虽然前面的段落已完整返回。

网络和接口响应成功不等于应用要求的结构化译文完整。以上是测试采集和输出处理共同暴露的问题，不能归为网站不可访问。初次对三个站各取一批的诊断均成功，但随后在生产并行调度路径中复现失败；不使用前一次成功掩盖后续失败。

## 改动

- 普通文本提示词不再引入保护占位符示例；真正带保护标记的文本仍要求逐项保留。
- 明确要求原句未完时也必须返回完整 JSON。
- 根据原段落编号提取有效译文，忽略无关的额外字段；不按顺序猜测对应关系。
- 返回格式受损时，只恢复语法完整且通过保护标记校验的字段；未闭合字符串不当作成功。
- 每条并行请求最多补译一次，只发送缺失或不合规段落。另一条正常请求继续工作，已经完整的段落不重复请求。
- 保护标记仍严格校验；补译仍失败时保留失败状态。取消、中断及网络错误不触发无条件重试。
- 汇总补译请求的词元和费用；最终失败时也保留已返回的用量。
- 后续测试保留行内代码文本，不从文本块中间硬截断；测试脚本使用生产 API 调度、合法数字编号，并记录错误类别。

## 验证

83 项自动化测试与快速静态检查通过。新增覆盖缺失段落的单独补译、额外字段过滤、保护标记损坏、损坏 JSON 中完整字段的保留、补译次数上限、补译期间取消和已知用量汇总。

最终真实 API 定点验证对 MDN、维基百科、BBC 各执行一个原始固定文本样本，三站均成功。MDN 使用 3 个请求，维基百科使用 3 个请求（含一次恢复请求），BBC 使用 4 个请求。见[最终验证记录](../reports/response-recovery-verification.json)。没有重新执行完整一百次测试，也未测量真实浏览器首屏绘制时间。

原来的 0.38 元账单仅对应原始一百次测试，本次诊断与验证的新增调用不包含在其中。旧[原始数据](../reports/benchmark-100-results.json)和[失败率及耗时](API_SAMPLE_TIMINGS.md)保留，不改写为修复后的结果。
