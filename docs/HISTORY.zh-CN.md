# 轻译 · DeepSeek 翻译 V2.9.0

Chrome Manifest V3 扩展。支持两种翻译方式、选中内容翻译和随滚动翻译网页。译文沿用原文颜色、字体、字重及行高，直接替换选中的文字或当前可见正文，保留原有链接与格式，不增加下方译文、背景、边框、标签或操作按钮。

## 安装

1. Chrome 打开 `chrome://extensions`，启用开发者模式。
2. 点击“加载已解压的扩展程序”，选择本项目的 `extension` 文件夹。
3. 更新源文件后，在扩展管理页点击“重新加载”，再刷新需要翻译的网页。

## 两种方式

- **不使用 Key · 网页**：使用已登录的 DeepSeek 专用会话。在扩展面板点击连接，选择专用标签页并确认。建议关闭深度思考和智能搜索。不要同时手动操作这个会话。
- **使用 Key · API**：在面板选择 API 模式，输入自己的 DeepSeek API Key，点击“保存 Key 并授权”。默认 `deepseek-flash`，关闭联网搜索和深度思考。无需打开 DeepSeek 网页。

Key 只保存在本机扩展存储，内容脚本不能读取；不写入源代码、不上传到项目服务器、不回显在面板。请求仅发往 `https://api.deepseek.com/chat/completions`，禁止重定向。可以随时点击“删除 Key”。

## 使用

- **选中内容**：选中文字，按 `Alt+Shift+T`，或右键选择翻译。为当前网站启用划选按钮后，也可以点击选区附近的“译”。
- **网页正文**：在当前网页打开扩展，点击“翻译网页正文”，优先处理正文并跳过导航、侧栏和页脚。
- **全部可读内容**：遇到网站规则造成漏译时，点击“翻译全部可读内容”、按 `Alt+W`，或在页面空白处右键选择同名功能。本次页面会翻译导航、侧栏、页脚以及网页误标为不翻译的普通文字；代码、密码、输入框、字体图标和敏感区域仍保持原样。
- **原位替换**：划选只替换实际选中的文字；页面翻译先处理当前可见正文，回复流式显示，并在后台批量准备下方内容。滚动到已准备的段落时直接显示，回看不重复请求。链接元素和地址保留。
- **技术内容保护**：跳过 `<code>`、`<pre>`、`<kbd>`、`<samp>`、`<var>` 和禁止翻译区域。API 路径、URL、文件路径、HTTP 方法、方法与路径组合、常见代码表达式保持原样，混排句子只发送普通正文。`/prefs/{where}` 这类拆分成多个链接的 API 导航标签同样保留。
- **纯文字阅读**：译文可直接选中复制；刷新网页可恢复原文。页面翻译期间，右下角进度条可以取消或恢复原文，当前屏幕处理完成后自动收起，继续滚动会自动翻译；再次点击面板中的页面翻译按钮可调出取消操作。
- **查看费用**：高级设置可导出最近 200 个任务的美元预估费用、token 用量和耗时，记录中不含 Key 和原文。

## V2.9 全部可读内容兜底

默认继续使用正文优先识别，减少导航和重复界面文字带来的费用。参考沉浸式翻译的“翻译网页/翻译整个页面”双入口，新增一次性的“翻译全部可读内容”和 `Alt+W` 快捷键。它用于处理网站正文规则不准、`translate="no"` 或 `.notranslate` 被误用造成的漏译；无需进入高级设置修改网站偏好。切换时会沿用正在运行的滚动翻译任务和缓存，不重发已经完成的文字。

强制范围只放宽页面区域和网页自带的禁止翻译标记，不放宽安全与技术内容保护。`code`、`pre`、`kbd`、`samp`、`var`、编辑框、密码、凭据、乱码、API 路径和字体图标仍不会发送。

## V2.8 滚动预翻译

当前屏幕处理完成后，默认提前翻译下方约 2 屏内容。高级设置可选择关闭或调整为 1–3 屏；范围越大，等待越少，但可能提前使用更多翻译额度。预翻译按 API 单批预算合并发送，结果先保存在页面内存中，不会提前替换屏幕外原文或改变布局。滚动到目标段落时直接显示已准备的译文，并立即开始准备更下方内容。

当前可见内容始终优先。快速跳到尚未准备的位置时，API 模式会取消已无关的后台预取，先翻译读者正在看的内容；网页模式保持单会话安全串行。页面隐藏、关闭预翻译或内容变成代码、敏感区域时，不再使用对应的预取结果。完整设计与验收见 [V2.8 滚动预翻译说明](../reports/V2.8_PREFETCH.md)。

### V2.8.1 Google 页面覆盖修复

文字按钮不再被统一排除；Google Ads 和 Google Business 页面会把导航、侧栏、工具栏及页脚作为可读界面翻译。Material Icons / Material Symbols 的 `refresh`、`help_outline`、`arrow_forward` 等字体图标继续保持原样，密码表单、编辑框和代码区域仍跳过。翻译只替换控件内的文字节点，不替换按钮本身，因此原有点击事件继续工作。

### V2.8.2 嵌入页面翻译

整页翻译会发现页面中具有实际显示尺寸的 iframe，并在用户点击“翻译整个网页”时请求对应嵌入网站的最小权限。授权后，主页面和每个可访问的嵌入文档分别扫描、排队和接收结果，互不覆盖。Google Developers 的 Trends API 页面因此可以继续翻译 `docs.google.com` 中嵌入的申请表单；输入框、密码、代码和隐藏 iframe 仍不会发送。

如果用户拒绝嵌入网站权限，主页面仍继续翻译，面板会明确说明嵌入内容保持原样。实现使用 Chrome 官方的逐 frame 内容脚本机制：[Content scripts / Frames](https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts#frames)。

## V2.7 技术句子与请求收集

同一文本节点内的技术混排句子采用整体翻译，路径、HTTP 方法、代码与术语以占位符保护并在本地恢复；纯代码仍跳过。占位符缺失或损坏时恢复原文。分段索引发现的可见内容在固定 80 ms 窗口收集合批，减少刚扫到少量文字就发送的情况；缓存规划改用索引查找。

划选翻译超过 200 ms 显示状态并可取消，立即命中缓存时不闪等待条。选区截断路径、动态页面修改路径均有回归覆盖。原位显示及样式继承保持。

新增对照 Read Frog、FluentRead、KISS Translator，见 [对照、实现与验证限制](../reports/V2.7_COMPARISON.md)。一次真实 API 验证中，3 句技术示例由 9 个片段变为 3 个单元，完整返回并恢复原值；这不代表请求数或实际速度提高 3 倍。Chrome 本地检查遇到自动审批超时，尚待人工验收。

## V2.6 API 并行与缓存修复

较大的当前可见批次最多使用两路 API 并行，短内容仍一次请求；重复片段先去重。网络流接收不再等待页面确认显示，进度合并为最新快照；任一路失败会中止另一路，不自动重发。缓存最多 1,500 条、30 分钟，仍受 4 MiB 总容量约束。导出记录增加请求数、后台排队和总处理时长。

18 段公开文档对照中，单请求两次为 4.64 / 7.48 秒，两路并行为 3.75 / 3.79 秒；但最终代码检查仍等了 8.08 秒才收到首 token，10.77 秒才完成。本版不能保证秒出或宣称追平竞品。详见 [完整对照与限制](../reports/V2.6_PERFORMANCE.md)。Chrome 自动化请求策略仍无法加载，尚待实际浏览器验收。

## V2.5 启动与持续阅读

- 启动时立即显示准备状态，优先建立当前屏幕附近的索引；全文索引分小段执行，不再等全部扫描完成才开始请求。每段扫描以 8ms / 160 次遍历为调度预算（不是实际耗时保证），之后让出执行，离屏内容仍不发送。
- 主题、样式变化不再触发全文卸载和重建；新增及删除节点按变化范围更新。密钥、代码和语言过滤移至可见内容进入请求前完成，避免启动时对所有离屏正文重复执行。
- 原文局部更新时保留同批仍有效的译文，重新处理变化部分；网络或回复中断时保留已完成部分，点击“继续翻译”重试剩余内容，不自动重复付费请求。
- 显示排队、发送、等待回复、流式显示等阶段；划选任务在待发送队列中优先，排队期限考虑前置任务截止时间。正在执行的任务不会被强制抢占，网页模式仍保持安全串行。
- 面板的多个独立读取并行进行。启动测试页 `/tests/startup.html` 包含 1,800 个离屏段落，可查看首请求时间、索引进度并模拟局部更新和中断；测量结果属于本地处理，不代表模型整体响应速度。

本轮对照的是 [DeepL 随滚动翻译和恢复原文](https://support.deepl.com/hc/en-us/articles/4407580229522-Translate-with-the-browser-extensions) 与 [沉浸式翻译站点范围和动态内容规则](https://immersivetranslate.com/docs/advanced/)。未实测竞品速度。Chrome 自动化工具本轮无法加载请求策略，因此本版仅完成自动化与静态检查，不能宣称浏览器实测通过。

## V2.4.1 合批优化

取消每批最多 6 个片段的限制，改为按实际发送数据量合批，最多 32 个可见片段。API 和网页模式分别以约 6,500 / 4,800 字符的数据预算分批；超长单片仍允许独立发送。相同上下文在一次请求中仅发送一份，各片段引用对应编号；返回格式保持不变，仍流式原位显示。

固定 24 个短片段、4 组重复上下文的分批检查中，旧策略需要 6 批，新策略 1 批；数据部分从 13,373 字符减少到 3,635 字符。这是合成样本的请求量检查，不是模型实际耗时或竞品速度测试。

## V2.4 样式、上下文与正文范围

- 译文继承原文颜色、字体、字重、行高等文字样式，跟随主题和链接悬停颜色变化；仍原位替换、可恢复原文。
- 混排片段携带最多 1,200 字符的句子上下文，用于理解语义，仍只输出对应片段；代码、路径和敏感区域不会作为上下文发送。相同文字的不同上下文使用独立缓存，避免多义词串用译文。跨语言语序与复杂 DOM 的完全重组仍有限制。
- 默认“正文优先”跳过导航、侧栏、页脚、目录等区域，另有 Reddit 和 GitHub 的特定排除规则。高级设置可按网站切换“全部可读内容”，代码和敏感内容保护始终保留；划选翻译不受正文范围限制。
- 高置信度识别已经是目标语言的内容；中文保留简繁转换，混合语言与无法确认的内容继续交给翻译。
- “Read more”等独立短语同批去重，跨批次或其他页面在缓存有效时复用；排队任务在发送前再次查缓存。缓存仍最多 1,500 条（受 4 MiB 总容量限制）、保留 30 分钟，语言或模式不同、缓存过期/清空/关闭后可能重新请求。

## V2.3 等待时间与误翻译优化

- 只建立一次初始正文索引，通过 IntersectionObserver 筛选可见段落；新内容通过 MutationObserver 增量更新。仍然不提前发送屏幕外内容。
- 缓存按文字、目标语言和翻译模式复用，不再依赖页面段落编号；同批相同片段只发送一次。部分命中缓存时立即显示已有译文，仅提交缺少的部分。
- API 流式显示不再逐次等待写入完整会话缓存；发送锁和最终状态仍持久化，避免意外重发。
- 跳过密码表单、敏感标记区域、常见代码编辑器、疑似密钥、凭据赋值、乱码、哈希和随机标识符。普通正文中的密码说明仍可以翻译。没有上下文的短密码无法保证识别，私密页面可在面板停用翻译。
- API、SDK、React、GraphQL、Docker 等技术术语原样保留；高级设置可添加自定义保留术语，每行一个，区分大小写。缓存最多 1,500 条（受 4 MiB 总容量限制）、保留 30 分钟，可以关闭或清空。

对比依据为官方功能文档：[沉浸式翻译正文与段落识别](https://immersivetranslate.com/docs/)、[排除规则](https://immersivetranslate.com/docs/advanced/)、[DeepL 滚动整页翻译与术语表](https://support.deepl.com/hc/en-us/articles/4407580229522-Translate-with-the-browser-extensions)。本次未做竞品速度实测。

V2.4 已加入上述三项基础能力。后续可继续扩展网站适配和复杂 DOM 的语序重组。网页模式仍受 DeepSeek 页面与专用会话响应速度影响。

## 范围与边界

- 划选每次最多 3,000 Unicode 字符。页面翻译先发送当前可见段落，再按设置提前发送下方 0–3 屏内容；不自动滚动。已授权且可访问的 iframe 会作为独立文档翻译；隐藏内容、编辑框、代码块、脚本和媒体仍跳过。
- 每次开启页面翻译累计最多 200,000 字符 / 1,500 段，以小批次流式翻译。网页模式批次较小，长页需要更久；复杂页面建议使用 API 模式。
- Chrome 内部页、扩展商店、PDF 和隐身页不支持。
- API 按实际 token 计费。显示的美元估算依据 2026-09-10 核对的官方峰谷价格，最终以 DeepSeek 账单为准。网页模式不使用 API Key，无法读取对应 token 费用账单。
- 翻译中的内容由用户选择后发送至 DeepSeek。网页模式会在专用聊天中保留消息；清理扩展数据不会删除网页聊天记录。
- 取消 API 请求不保证远端已停止计费。网页模式仅在确认自己任务和远端状态后解除串行锁；不确定的请求不会自动重复发送。
- 设置与 Key 存在本机，临时译文和用量记录保存在浏览器会话中。恢复默认设置保留 Key；删除 Key 使用单独按钮。
