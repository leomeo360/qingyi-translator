## 已实现

1. **减少技术内容造成的碎片。** 同一文本节点里的正常句子遇到 API、路径、反引号代码或自定义术语时，保留为一个翻译单元，原值留在本地。发送占位符，译文可按目标语言语序调整标记位置，然后本地恢复。GET 与紧邻路径一起保护。纯代码、敏感内容仍跳过；超长文本、超过 16 个保留区或选区截断技术内容时走原有片段流程。
2. **严格保护原文。** 最终结果缺失、重复或伪造占位符会报错并恢复原文，不自动重新付费请求。流式显示隐藏不完整标记。修复半截路径选区可能被翻译，以及动态页面修改路径后可能恢复旧值的问题。代码 DOM、颜色、字体、链接元素沿用原有规则。
3. **首屏短窗口收集。** 分段索引继续进行，不等全文结束；同一轮 80 ms 内发现的可见内容一起参与合批，避免每个扫描小片刚结束就发送。窗口从首次事件起计时，不因持续滚动或 DOM 变化反复重置。
4. **更快的缓存规划。** 不再对每一个缓存项反复序列化同一个片段。缓存最多 1,500 条、30 分钟、4 MiB 的限制保持。相同占位符句型可以复用译文，各页面在本地还原自己的路径；上下文仍参与缓存身份。
5. **划选等待可见、可取消。** 超过 200 ms 显示阶段状态和取消操作；缓存立即命中时不闪出等待条。取消恢复这次选区的原文，旧进度不再覆盖页面。没有给每段译文增加装饰或操作元素。

## 快速验证与实际限制

- 60 项快速自动化测试通过，包含本轮占位符往返、半截路径选区、动态路径更新、80 ms 收集、选区取消与缓存索引。使用受控 DOM 的测试不等于 Chrome 渲染验收。
- 固定 1,500 条缓存、32 个带上下文片段，各计时一次：缓存键读取 48,000 → 1,500 次，本地规划约 124.77 → 1.22 ms。这不是 API 或整页提速倍数。
- 一次真实 DeepSeek 请求验证 3 句固定技术示例：旧提取方式 9 个片段，新方式 3 个单元；实际请求仍是 1 次，不能说请求数减少 3 倍。首 token 2.033 秒，完成 2.504 秒，所有 API、HTTP、路径、React、Docker 与反引号代码正确还原。预估 USD 0.0001059，非账单。
- 原始记录：[api-protected-sentences.json](api-protected-sentences.json)。该记录只含合成公开示例与用量，不含 Key。复现脚本在源项目 `scripts/verify-protected-api.mjs`。
- 本轮尝试在外部 Chrome 打开本地检查页，自动权限审批等待超时，未确认进入页面，没有绕过限制。已停止本轮临时预览服务。Chrome 中的样式、滚动及真实扩展交互仍需人工验收。

**仍未解决：** DeepSeek 首次响应的波动、跨多个链接/粗体节点的整句语序重组、跨页面任务共用队列，以及站点规则覆盖。前轮出现过 8.08 秒才收到首 token，本轮 2.03 秒的单次结果不能证明这个问题消失。本版继续使用已选 DeepSeek 服务，未新增其他接收网页内容的服务。
