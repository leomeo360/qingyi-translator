# V2.6：API 等待时间与竞品对照

2026-09-12。结论：插件中确有缓存失效和流处理阻塞，已修复；两路并行在小样本中缩短了整批生成时间，但最终实网检查仍出现 8 秒首次响应等待。本版不能宣称已经达到成熟插件的速度。

## 官方资料能确认什么

| 对照产品 | 已核实的能力 | 对我们的启示 |
| --- | --- | --- |
| 沉浸式翻译 | 可选择 Google、Microsoft、DeepL、DeepSeek 等引擎。[官方说明](https://immersivetranslate.com/en/compare/immersive-translate-vs-deepseek/) | 应在同网页、同模型、同语言下比较插件；跨引擎的速度差不能直接归因于插件。 |

DeepSeek 官方允许 API 并发，也明确请求有时会等待服务器响应，流式连接可能只收到 keep-alive。[限速与隔离](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit/)。这支持使用少量并行，但不是首次响应时间的保证。没有实际安装或测量上述竞品，本表不是性能排名。

## 本次完成的修改

- 较大可见批次使用最多 2 路 API 并行：至少 4 段、正文总计至少 1,800 字符，拆分后每路至少 400 字符。短内容一次发送；优先沿上下文边界拆分，仍只处理已收集的可见内容。重复内容先去重再拆分。
- 读取 SSE 不再等待页面进度确认。最多一个进行中的显示回调和一个最新快照，合并中间进度；成功前刷新最终结果。任一路失败中止其他路，不自动重发。
- 缓存由 100 条扩大到最多 1,500 条，仍保留 30 分钟，受 4 MiB 硬容量限制。修复长页面顺序阅读造成的缓存淘汰循环。150 个不同片段按每批 32 个读取两遍，第二遍远程片段数由 150 降至 0（受控回归测试，不是实网速度）。
- 导出记录新增请求数、后台排队时长和后台接单至结束的耗时。原 `firstTokenMs` 仍表示 API 开始调用到首 token，不能代表点击至屏幕显示；本地 DOM 扫描和实际绘制要由页面测量。

## 真实 API 小样本

输入：已有公开 Python 文档快照的 18 段、4,437 个正文字符。使用生产 API 模块、`deepseek-flash`、关闭思考与工具、无本地译文缓存。只测这一批，不代表完整网页或用户实际慢的网站。

| 次序 | 策略 | 请求数 | 首段有至少 20 个译文字元 | 本批完成 |
| --- | --- | ---: | ---: | ---: |
| A1 | 单请求 | 1 | 1.365 秒 | 4.635 秒 |
| B1 | 平衡拆分、两路并行 | 2 | 1.953 秒 | 3.749 秒 |
| B2 | 平衡拆分、两路并行 | 2 | 1.897 秒 | 3.786 秒 |
| A2 | 单请求 | 1 | 4.260 秒 | 7.484 秒 |
| 最终代码检查 | 正式批处理模块、两路并行 | 2 | **8.298 秒** | **10.767 秒** |

最后一次的 API 首 token 为 **8.078 秒**，延迟发生在得到译文内容之前。此数据符合远端等待或网络波动的表现，但没有服务端追踪，无法单独归因于模型排队。

前四次两种策略各只有 2 个样本，且同一文本多次请求会受到服务端提示缓存影响。两路请求的输入 token 从 1,182 增至 1,344；并发会重复一部分提示，不能宣称降低费用。合计 8 个请求预估约 USD 0.00289，按项目现有价格估算，非账单。最终检查保留了慢样本，因此不发布总体提速倍数。

原始无凭据记录：`api-latency-diagnosis.json`。复现脚本：`../scripts/benchmark-latency.mjs`；默认执行 A/B/B/A 对照，`--production` 在已有记录上追加一次最终模块检查。Key 从标准输入读取，不写入报告。

## 仍有差距

1. **首次响应不稳定**：本地调度不能消除 API 首 token 前的等待。专用翻译引擎可以作为下一步可选方案，实际速度仍需同页测量；本版没有自动切换服务或新增数据接收方。
2. **复杂混排仍按片段输出**：上下文已去重，但大量链接、粗体、术语会生成多个 JSON 项。下一步应设计整句翻译与 DOM 样式映射，避免破坏代码、链接和原样式；本版没有声称完成句子级重组。
3. **跨页面任务仍共用队列**：本次并行仅在一个当前可见批次内。划选可优先排队，不能抢占正在执行的任务。
4. **真实 Chrome 验收未完成**：浏览器工具先前连续两次无法加载请求策略；没有绕过工具限制。48 项快速自动化测试、静态检查，以及上述 API 调用不等于用户界面的性能验收。
